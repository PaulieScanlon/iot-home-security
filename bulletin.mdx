Before an agent sees a single Ring event, each Ring account has to be linked with a token exchange, and every webhook Ring sends has to be verified against its signature. Ring also doesn't give out shareable links to its media. `RingSignals` adds the routes Ring calls to your Mastra server, refreshes each account's tokens before they expire, and serves snapshots and clips as signed links from your own server.

## Get started

Install Ring signals with the storage and memory packages:

```bash title="Terminal"
npm install @mastra/ring-signals @mastra/libsql @mastra/memory
```

<Note>Requires `@mastra/ring-signals@<version>` and `@mastra/core@<version>` or later, added in [PR #<PR>](https://github.com/mastra-ai/mastra/pull/<PR>).</Note>

Add `RingSignals` to the agent's `signals` array, so each Ring event (a doorbell press or motion) arrives in the agent's thread as a notification signal:

```typescript title="src/mastra/agents/home-agent.ts"
import { Agent } from "@mastra/core/agent";
import { Memory } from "@mastra/memory";
import { RingSignals } from "@mastra/ring-signals";

export const homeAgent = new Agent({
  id: "home-agent",
  name: "Home Agent",
  instructions: "Watch the front door and say briefly whether each event needs attention.",
  model: "openai/gpt-5-mini",
  memory: new Memory({
    options: {
      observationalMemory: true
    }
  }),
  signals: [new RingSignals()]
});
```

Register the agent and a storage adapter on the Mastra instance:

```typescript title="src/mastra/index.ts"
import { Mastra } from "@mastra/core";
import { LibSQLStore } from "@mastra/libsql";
import { homeAgent } from "./agents/home-agent";

export const mastra = new Mastra({
  agents: { homeAgent },
  storage: new LibSQLStore({
    id: "mastra-storage",
    url: "file:./mastra.db"
  })
});
```

### Multi-player alerts

To enable multi-player alerts

By default, `RingSignals` sends events to its own thread, using the device ID as the `threadId` and the agent's `id` as the `resourceId`. To get Ring alerts in a [channel](https://mastra.ai/docs/channels), set `target` and the channel's `resolveResourceId` and `resolveThreadId` to the same values.

This example uses [iMessage](https://mastra.ai/blog/introducing-imessage-support). Install the iMessage adapter:

```bash title="Terminal"
npm install @photon-ai/chat-adapter-imessage
```

Point the iMessage channel and `RingSignals` at the same thread:

```typescript title="src/mastra/agents/home-agent.ts"
import { Agent } from "@mastra/core/agent";
import { Memory } from "@mastra/memory";
import { RingSignals } from "@mastra/ring-signals";
import { createiMessageAdapter } from "@photon-ai/chat-adapter-imessage";

const resourceId = "home-agent";
const threadId = "ring-alerts";

export const homeAgent = new Agent({
  // ...
  id: resourceId,
  channels: {
    resolveResourceId: () => resourceId,
    resolveThreadId: () => threadId,
    adapters: {
      imessage: { adapter: createiMessageAdapter() }
    }
  },
  signals: [
    new RingSignals({
      target: { resourceId, threadId }
    })
  ]
});
```

For more information and full configuration options, see:

- [RingSignals reference](https://mastra.ai/reference/signals/ring-signals)
- [Ring integration guide](https://mastra.ai/integrations/channels/ring)
- [Notification signals](https://mastra.ai/docs/signals/notifications)
